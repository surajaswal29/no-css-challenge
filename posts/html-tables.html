Tables are for data

A table shows information in rows and columns: timetables, prices, results. When the content has that shape, a table is the most accessible way to present it, because assistive technology can announce each cell with its headings.

The basic structure

<table>
  <caption>Opening hours</caption>
  <tr>
    <th scope="col">Day</th>
    <th scope="col">Hours</th>
  </tr>
  <tr>
    <td>Monday</td>
    <td>9:00 to 17:00</td>
  </tr>
</table>
<table>
The table itself
<caption>
A title, read first by screen readers
<thead / tbody / tfoot>
Groups of header, body and footer rows
<tr>
A row
<th>
A header cell; add scope to say what it labels
<td>
A data cell

A simple table

Soft horizontal lines come from frame="void" and rules="rows", and alternating row colours from bgcolor on each <tr>:

Name Age City
Mira 25 Kyoto
Tomas 30 Lisbon
Anaya 28 Pune

Captions and row groups

With <thead>, <tbody> and <tfoot> in place, rules="groups" draws a line only between the groups:

Tea shop sales, first quarter
Month Sales Profit
January $1,000 $200
February $1,200 $240
March $1,450 $310
Total $3,650 $750

Spanning rows and columns

colspan and rowspan let one header cover several columns or rows. scope="colgroup" and scope="row"Footnote 1. Without scope, screen readers guess which cells a header labels. With it, they know. keep the relationships clear:

Student grades
Student Subjects Average
Math Science English
Alice 85 90 88 87.7
Bob 92 88 85 88.3
Chen 78 94 91 87.7

Styling without CSS

Every table on this page is styled with attributes alone. Here they are, in a table of course:

Presentational table attributes that still work in every browser
Attribute What it does
border Width of the outer border; also turns on cell borders
frame Which outer sides to draw: void, hsides, box…
rules Which inner lines to draw: rows, cols, groups, all
bordercolor The colour of those lines
cellpadding Space inside every cell
cellspacing Space between cells
bgcolor Background of a table, row or cell
align / valign Horizontal and vertical alignment
width / height Preferred size, in pixels or percent
Good to know
These attributes are obsolete for new websites, but the HTML standard still defines exactly how browsers must render them. That is why this whole blog can exist.

Good habits

  • Use tables for tabular data, not page layout (this blog breaks that rule on purpose)
  • Always add a <caption>
  • Use <th> with scope for every header
  • Right-align numbers so digits line up
  • Keep tables narrow enough to read on a phone
Try it yourself

Build a two-column table of your week: days on the left, one calm thing for each day on the right. Give it a caption.

Show the solution

<table border="1" rules="rows"
  frame="hsides" cellpadding="8">
  <caption>A calmer week</caption>
  <tr>
    <th scope="col">Day</th>
    <th scope="col">Calm thing</th>
  </tr>
  <tr>
    <td>Monday</td><td>A walk</td>
  </tr>
  <tr>
    <td>Tuesday</td><td>Tea</td>
  </tr>
</table>

In short

Give tables a caption, headers with scope and sensible groups, and they will serve every reader. Next up: HTML Forms: A Complete Guide.
