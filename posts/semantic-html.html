What is semantic HTML?

Semantic HTML means choosing the element whose meaning matches your content. A navigation bar is a <nav>, not a <div class="nav">; a date is a <time>, not just some text.

Browsers, search engines and screen readers all read that meaning and use it to help people.

Why it matters

  • Accessibility. Screen reader users can jump straight to the navigation, the main content or the next heading
  • Search. Search engines understand what your page is about
  • Maintenance. <article> tells the next developer far more than <div>
  • Free features. Reader modes, outlines and translation tools all work better

Landmarks: the map of a page

LandmarksFootnote 1. Try it: most screen readers list landmarks with a single shortcut, for example D in NVDA or the rotor in VoiceOver. divide a page into regions that assistive technology can list and jump between.

Landmark elements and the roles they give to assistive technology
Element Role Use it for
<header> banner Site title, logo and main navigation
<nav> navigation A group of important links
<main> main The unique content of this page (only one)
<article> article A self-contained piece, like a post
<section> region* A themed group with its own heading
<aside> complementary Related content, such as a tip
<footer> contentinfo Copyright, contact and small print
<search> search A search form

* A <section> only becomes a region when it has an accessible name.

Small elements with big meaning

<time> dates and times

Machine-readable dates: <time datetime="2024-03-10">. Here: 10 March 2024.

<mark> highlighted text

Text that is relevant right now, such as a search match.

<dfn> the defining instance of a term

A landmark is a region of a page that assistive technology can jump to.

<cite> the title of a work

<abbr> abbreviations

Screen readers can expand ARIA for listeners.

<figure> self-contained media with a caption

Group an image, chart or code sample with its <figcaption>.

Before and after

The same page skeleton, written twice:

Without meaning
<div id="header">
  <div class="nav">
    <div class="menu">...</div>
  </div>
</div>
<div id="main">
  <div class="content">...</div>
</div>
With meaning
<header>
  <nav>
    <ul>...</ul>
  </nav>
</header>
<main>
  <article>...</article>
</main>

Both look identical. Only the second tells the browser what each part is.

Semantics in action

<article>
  <header>
    <h2>Morning pages</h2>
    <p><small>By Asha,
      <time datetime="2024-03-10">
        10 March</time></small></p>
  </header>
  <p>Three pages, first thing,
    <em>every</em> day. It is
    <mark>simpler</mark> than it
    sounds.</p>
  <footer>
    <small>Filed under habits</small>
  </footer>
</article>

Good habits

  • Use headings in order and do not skip levels
  • Reach for a semantic element before a <div>
  • Use <button> for actions and <a> for navigation
  • Add ARIA only when no HTML element fits
  • Have exactly one <main> per page
Try it yourself

Which element would you use for: a blog post, a list of the site's main pages, and a publication date?

Show the solution

  • A blog post: <article>
  • Main pages: <nav> with a <ul> inside
  • Publication date: <time datetime="…">
